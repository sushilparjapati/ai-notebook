Revision Notes · RAG Series

Self-RAG

The model grades its own retrieval and its own answer — inline, with reflection tokens, no external evaluator.

Self-Reflective

Why let the model grade itself?

CRAG's evaluator sits outside the model. Self-RAG pushes the same instinct — check before you trust — inside the model's own turn, both before and after it answers.

✕ Naive RAG

retrieves every time, never re-checks

question→ always retrieve→ generate

Even a general-knowledge question pays the retrieval cost, and the final answer is never re-examined.

✓ Self-RAG

decides, then double-checks itself

question→ Retrieve?→ generate→ ISSUP / ISUSE

Skips retrieval when unneeded; after answering, checks its own grounding and usefulness before returning.

The four reflection tokens

Each is a small structured decision the model makes about its own process, at a different point in the turn.

Retrieve
do I even need documents for this?
ISREL
is this specific chunk relevant?
ISSUP
is my answer supported by context?
ISUSE
does my answer actually help?

ISUSE — is the grounded answer actually useful?

A grounded answer can still dodge the question. ISUSE checks that separately, and can trigger a query rewrite + re-retrieve instead of just a re-answer.

"Describe NexaAI's company culture" (step7)
fully_supported → "The answer provides specific details about NexaAI's company culture."
isuse: useful → END
"What is refund policy of NexaAI" (step6)
burns all 10 ISSUP retries, still unsupported — corpus genuinely has no refund policy chunk
isuse: not_useful → no_answer_found

Glossary

Retrieve
token deciding whether retrieval is needed at all.
ISREL
token: is this specific chunk relevant?
ISSUP
token: is the answer supported by context? fully / partially / no_support.
ISUSE
token: does the supported answer actually address the question?
revise_answer
forces a strict quote-only rewrite when ISSUP fails.
rewrite_question
rewrites the retrieval query when ISUSE fails, then retries retrieval.

Self-test

Why check ISSUP and ISUSE separately?
They catch different failures — ISSUP catches ungrounded wording even in an on-topic answer; ISUSE catches grounded-but-non-answering responses. One combined check would miss whichever failure mode isn't explicitly asked about.
Why did the correct "14-day free trial" answer get marked no_support?
ISSUP grades literal textual grounding, not factual correctness — "supported" and "true" aren't the same check.
What's the real difference between the ISSUP-revise loop and the ISUSE-rewrite loop?
revise_answer only changes the wording of the answer from the same context; rewrite_question changes the retrieval query and fetches new documents entirely.
How does the web branch relate to CRAG's corrective action?
Same idea — replace bad retrieval with a web search — triggered by a different signal: CRAG uses an external evaluator's verdict, Self-RAG uses ISREL finding zero relevant chunks.
